# B3 candidate design, not adopted or measured

Evidence: a4-economy-audit.json. All 1,350 account-days per style saturate 180 stamps; each account has 58 paid draws by day45, so a 60-mark selector is unreachable. The same invitation seed schedule plus identical paid-draw counts explains identical first-Legendary dates. No new acceptance seeds have been sampled.

First candidate to test AFTER B1/B2: keep earned invitation price 150, base rarity odds and duplicate/featured rules; v4-only stamp cap 480 (the existing sandbox account cap), selector cost 40 marks, soft pity from paid draw10 in each group with +5pp conditional Legendary chance per draw, hard guarantee draw24. Preserve existing earned marks and pity: a saved counter already beyond the new guarantee awards its next Legendary, never resets or removes progress. Welcome remains free and gives no mark. OFF constants and historical sampling stay unchanged. These values are hypotheses, not results.

Rationale: make an ordinary service + one route earn roughly 1–2 invitations, two routes roughly 2–3, and six routes no more than the shared 480-stamp cap (~3.2). Today's two services and board rewards remain the same; more routes can make a bounded difference before the cap. Two weeks should contain a visible Legendary chance and a reachable chosen reward, while heavy/casual earned ratios must still be measured <=3 for EVERY currency and paid draws. Do not infer command outcomes from this budget arithmetic.

Implementation scope: add a v4 banner descriptor and odds function in depth/gacha-v4.ts, implement cat draw path with identical partition/duplicate semantics alongside the current gear draw path, and make getDrawPoolV4 use the same exact conditional odds. Expose the descriptor to invitations UI and the 10k-account sim. Keep src/config.ts, bridge/Relic/Fuji paths and legacy gacha source unmodified. Dynamic depthCaps(state) chooses 180 OFF / 480 ON stamps; grantDepth, board/service previews, meta-command clamping and UI cap copy all use the same mode-aware table. Historical earned amounts are not subtracted when switching modes; only newly requested rewards are capped. No state field is planned for this change, so migration tests must prove THC7/THC12 import and unchanged balances in both modes.

Pending proofs: actual 90-account/45-day command sim; day7 first-two-attempt retry recommendation; complete 10k accounts per banner and CDF test; first-Legendary dates including gear drops and selectors reported separately from banner-only CDF; no injected currency/levels; caps and rollback tests; current odds/help/spec updated together. Keep A4 receipt comparisons. This design does not select a production tuning before those train checks.
