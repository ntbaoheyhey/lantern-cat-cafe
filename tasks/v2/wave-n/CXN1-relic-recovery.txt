PIECE 3 - Re-issue race guard (proposal "Duplicate guard")
Problem: a mint is mined just before expiry, the RPC is behind, the server re-issues, both vouchers can mint.
1. Before re-signing an expired voucher, require nowS > expiry + REISSUE_GRACE_SECONDS (exists) AND read
   nonceUsed again AFTER the voucherReissue store call. If the old nonce is now used: mark the forge's old
   voucher minted (tx hash null), mark the NEW voucher cancelled on the server, and return the minted state.
   The new voucher must never reach the client in that case.
2. If this needs a new SQL function (for example game_voucher_void(p_player, p_nonce)), add ONE migration
   file supabase/migrations/20261107000000_voucher_race_guard.sql (additive, idempotent, service_role only,
   same style as 20261106). This file is allowed for this mission only. Never apply it.
3. Update docs/proposals/relic-recovery.md status line: fixes 2, 3 and the race guard implemented, migration
   not applied, apply before deploy.
