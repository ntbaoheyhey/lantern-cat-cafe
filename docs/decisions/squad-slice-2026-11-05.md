# Squad slice numerical decisions · 2026-11-05

All new tunables live in `packages/game-rules/src/squad/config.ts`, re-exported by
`packages/game-rules/src/config.ts`. The verified rule tables are unchanged. All times
are milliseconds unless named otherwise; stats are points, fractions are explicit.

## Evaluation order

Base stats × preset once → sum same-kind modifiers → cap once → skill multiplier
→ seeded ±8% variance → critical multiplier → exposed-knot multiplier → diminishing
defense `80/(80+defense)` → summed/capped guard → round once → shield → HP.
Cleanse precedes heal, heal precedes shield. Heals never revive. Damage can consume shield
and HP in one impact. Events carry resolved values; the presenter never recomputes them.

## Observed tuning history

Initial headless study: both presets won all seeds, but active marking was slower because
the healer stood inside ordinary AoE. That did not meet the target-choice gate.
- Healer HP 195 → 245; healing 46 → 85; anchor (468,145) → (584,123): a real protected backline problem.
- Ultimate charge per second 4 → 2; per hit 3 → 2: barriers should not be permanently available.
- Hearthwall shield 100 → 70; Nine-Lives shield 95 → 65: preserve recovery windows.
- Yarn Giant HP 3600 → 4300; attack studied at 60/100/300 then finalized at 170 after separating add anchors. Combined 20-seed study: sustain auto 18/20, active 20/20; burst both 20/20.
- Ordinary attacks guard 23 → 58, flanker 14 → 35, ranger 21 → 53, charger 37 → 93, elite 38 → 95: support now has visible work while patrol remains survivable.
- Boss adds use a separate eight-slot formation (full coordinates below), avoiding overlap with the giant. The old overlapped-anchor balance results are invalid.
- Opening role slots guard/charger/flanker/flanker → guard/flanker/flanker/charger: Thread Snare and Ember Orb lock the guard plus both small enemies while Rally redirects the later charger. A real-seed test checks the injured-Guardian heal.
- Exact raw tuning studies are in reports/squad/logs/*study.log. Active means target marking only; both arms keep auto ultimates.
These are prototype tuning judgments; `balance.json` supplies controlled outcome evidence, not human fun data.
