## 1. A readable turn, with choices

Use a deterministic speed-based initiative queue, one slot per living actor. Ties use
seeded initial initiative then stable actor ID. The next eight slots include future
rounds. Only `startTurn → chooseAction → resolveAction → endTurn` advances combat;
wall time never advances rules. A hero waits indefinitely for skill + legal target.
Each cat may opt into Auto. The controller waits for every presentation beat before
starting another slot, even at ×4 or after Skip. Input locks at action selection.

Retain all three basics, nine activated skills, three passives, six enemy roles, waves,
both existing loadout presets, and Yarn Giant. The old engine stays available for the
explicit 2D comparison/fallback; existing consumers and their tests remain unchanged.
The turn engine shares the cast, role names, encounter compositions and skill identities,
but has separately tuned numbers. All new tuning is exported from `config.ts`.

Durations and cooldowns use the affected actor's own turns. A newly applied two-turn
guard protects through two subsequent turns; burn ticks at turn start, then durations
decrease at turn end. A skill with cooldown 2 is unavailable on the next two own turns.
Shields expire after their owner's two turns. Taunt redirects hostile single targets;
cleanse removes harmful effects. Shield Bash interrupts the queued enemy intent and
delays its slot; Thread Snare delays a selected row. Delay/advance reorders one existing
slot, never inserts duplicates. Boss control has bounded resistance. Charge comes from
actions and damage received, never idle time; an ultimate consumes an ordinary action.

Enemy intents are committed before the player chooses: action icon, name, target and
turn countdown appear both above the actor and in the tactical panel. Invalidated dead
targets visibly retarget; taunt and interrupt explicitly announce intent changes.
Boss cycles Sweep → Loose End → Cross Stitch (phase two); countdown is in boss turns.
Destroy the separate Binding Thread to release its captive and expose the knot for two
boss turns. A visible stagger meter offers another opening. Enrage prevents stalling.

At 1280×720: retained left navigation and top HUD, eight-slot turn bar, battlefield
occupying about 72% of combat width, intent panel, party cards, four active-cat skill
buttons. Current actor + “Choose a skill / Choose a target / Resolving…” is always
visible. Hotkeys 1–4 select skills; accessible target buttons mirror the scene. Target
preview marks all affected actors and explains invalid selections. No modal confirms.

## 2. Original miniature diorama and event choreography

Choose three.js, lazy-loaded only inside the guest `squadCombat` entry. An opt-in
`squad3d=1` sub-flag selects the new runtime; both feature flags default false. Keep DOM
controls and the pure rules core outside the renderer. No scene module imports an
engine function. Render snapshots are projected from resolved events; presentation
never rolls damage. A WebGL failure retains a playable DOM turn battlefield.

Look: a small round cafe rug on a honey-colored wooden table, dusk backdrop, warm key,
cool rim, soft blob shadows, teacups, stacked books, candle and planter. Rounded low-poly
geometry with matte/toon-like materials, small rim accents and dark facial marks;
avoid a full postprocessing chain. Cheap additive glow sprites, rings and ribbons give
soft bloom within a strict pool. Fixed orthographic three-quarter camera makes the
silhouettes legible; focus/push/shake/victory orbit are scripted offsets, never free-look.
Mochi: cream + amber, shield and ladle. Soot: charcoal + violet, hat and floating lantern.
Clover: mint + teal, flask satchel and leaf collar. Enemies remain household creatures.

Every action maps to data in an effect registry: anticipation, travel, impact, reaction,
residue. Each resolved event carries sequence, slot, actor ID, action ID, target IDs,
resolved numbers, beat index and actor snapshots. The presenter consumes only this
stream. Routine anticipation 250–400ms, ultimate/danger anticipation 850–1100ms;
impact freeze 60–100ms. Ultimates focus the caster, dim the backdrop, show a name
flourish and signature light, then restore the wide shot. Timings are data, not skill
branches in the scene. Reduced motion removes camera offsets, shake and flashes;
numbers, colors, outlines and statuses remain. ×1/×2/×4, fast mode, pause and skip
are available. Effects gallery uses fixed event fixtures; model viewer uses the same
GLBs and clip names as battle. Deterministic seed/time capture is a separate debug mode.

## 3. Pipeline, budgets and delivery gates

No Blender installed. glTF Transform CLI 4.5.1 is available through npx. Use original
procedural three.js geometry, authored in `tools/art3d/` or a shared source module,
exported with GLTFExporter to GLB with named part animation tracks. Runtime loads the
GLBs; offline builder embeds bytes and uses GLTFLoader.parse, with no file:// fetch.
Commands: `pnpm art:turn3d` builds models + hashes + triangle report;
`node tools/turn3d/capture.mjs` captures native turnaround/model/effect fixtures;
`node tools/turn3d/demo.mjs` compiles the actual runtime into `docs/turn3d/index.html`.
No downloaded models/textures or reference-game art. Tool/script, parameters, date,
author, output hash, triangle count and license go in `docs/turn3d/ASSET-MANIFEST.json`
and `assets/provenance/turn3d.md`. Runtime libraries: three.js 0.180.0 (MIT), existing
React 19.3.1 (MIT). Build-only @types/three 0.180.0 (MIT); existing Vite 8.3.5 (MIT).

Initial balance target: 20–35 actions per wave, 60–90 seconds including choices; full
three waves + boss 6–8 minutes at normal speed with human decisions. This is a design
target, not a measured claim. Two presets × Auto/active priority × ≥30 seeds will report
wins, turns, deaths, first death role and boss success. Automated timing excludes human
thinking; do not manufacture a play-duration result from it. Tune only turn config.
