# Extending Cat RPG v2

Step-by-step developer recipes for modifying and extending the Cat RPG v2 content registry. Each recipe details every file to touch, the exact error messages and tests that fail if a step is omitted, and the commands to verify your changes.

---

## Fundamental Rules

1. **Numbers live in config:**  
   Every balance multiplier, drop rate, stage curve, and combat duration lives in [`packages/game-rules/src/v2/config.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/config.ts) (`V2_CONFIG`), never hard-coded in logic.
2. **Relic tiers are append-only:**  
   Relic tokens are pinned on-chain 1:1 with rarities (Common = 1, Rare = 2, Epic = 3, Legendary = 4; see [`packages/game-rules/src/content.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/content.ts) and `relicIdOf`). Existing Relic tiers can never be reordered, altered, or deleted without invalidating existing on-chain tokens.
3. **Registry integrity via validation:**  
   All content definitions are checked for referential integrity, unique identifiers, and game balance constraints by `validateContent()` in [`packages/game-rules/src/v2/content/validate.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/content/validate.ts).
4. **Documentation cannot drift:**  
   [`docs/content-v2.md`](file:///Users/bao/taskbar-hero/docs/content-v2.md) is autogenerated from code. Continuous integration asserts disk content matches the in-memory registry via [`packages/game-rules/src/v2/content/docs.gen.test.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/content/docs.gen.test.ts). After changing content, always run `node scripts/gen-content-docs.mjs`.

## Recipes

### 1. Add a Gear Item

Gear items belong to one of 9 slots across 5 rarities (`common`, `uncommon`, `rare`, `epic`, `legendary`). Base stats represent level 1 stats before rarity and level scaling.

#### Steps
1. Open [`packages/game-rules/src/v2/content/items.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/content/items.ts).
2. Choose the category for the item:
   - **Weapons:** Add the name pair `[idSuffix, displayName]` to `WEAPON_NAMES[weaponType]` for all 5 rarities.
   - **Armor pieces:** Add a new `ArmorSetDef` to `ARMOR_SETS` (specifying pieces and rarity prefixes).
   - **Accessories:** Add an `AccessoryDesign` to `ACCESSORY_DESIGNS` (4 slots × 3 designs).
   - **Standalone / unique gear:** Define an explicit `ItemDef` object conforming to `ItemDef` and include it in `ITEMS`:
     ```typescript
     {
       id: 'acc.charm.fishbone.common',
       slot: 'charm',
       rarity: 'common',
       name: 'Plain Fish Bone',
       baseStats: { fishBonus: 0.04 },
       visual: { set: 'fishbone', palette: 'common' },
       dropChapters: [1, 2, 3, 4, 5],
     }
     ```
3. Item constraints enforced by `validateContent()`:
   - `id` must match `STORED_ID` (`/^[a-z0-9.]+$/`).
   - `slot` must exist in `GEAR_SLOTS`.
   - `rarity` and `visual.palette` must exist in `GEAR_RARITIES`.
   - `weaponType` must be set if and only if `slot === 'weapon'`.
   - `baseStats` on main slots (`helmet`, `armor`, `gloves`, `boots`, `weapon`) must provide all `slot.primaryStats`.
   - `baseStats` on accessory slots (`collar`, `earring`, `ring`, `charm`) must carry secondary (fractional) stats only—flat `hp`, `atk`, or `def` are rejected.
   - `dropChapters` must not be empty and must reference valid chapter indexes (1..5).
4. Regenerate documentation:
   ```bash
   node scripts/gen-content-docs.mjs
   ```
5. Update snapshots and tests:
   ```bash
   pnpm --filter @taskbar-hero/game-rules test src/v2/content/content.test.ts -u
   ```

#### Failure Output on Missed Steps
If you add an item without regenerating docs or updating snapshots:
```
FAIL src/v2/content/content.test.ts > v2 content registry > has the planned amounts of content
AssertionError: expected [ { ...(7) }, ... ] to have a length of 60 but got 61

FAIL src/v2/content/content.test.ts > v2 content registry > snapshots every item id so renames show up in review
Error: Snapshot `v2 content registry > snapshots every item id so renames show up in review 1` mismatched
+ "acc.charm.fishbone.common"

FAIL src/v2/content/docs.gen.test.ts > v2 content docs generator > writes docs/content-v2.md when UPDATE_DOCS=1 and matches disk contents otherwise
AssertionError: expected docs/content-v2.md on disk to match generated output
```

### 2. Add a Monster to a Chapter

Monsters are defined per chapter with archetype multipliers (`balanced`, `swift`, `sturdy`, `elite`, `boss`) applied on top of stage formulas.

#### Steps
1. Open [`packages/game-rules/src/v2/content/monsters.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/content/monsters.ts).
2. To add a standard chapter monster, update `ROSTER` or append a `MonsterDef` to `MONSTERS`:
   ```typescript
   {
     id: monsterId('Fluff Ball'), // 'mon.fluff.ball'
     name: 'Fluff Ball',
     chapter: 1,
     kind: 'regular',
     ...ARCHETYPE.balanced, // hpMul: 1, atkMul: 1, xpMul: 1, lootMul: 1
   }
   ```
3. Chapter roster binding in [`packages/game-rules/src/v2/content/chapters.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/content/chapters.ts):
   - Regular monsters are automatically gathered by `byKind(index, 'regular')`.
   - If adding an Elite or Boss, update `ch.elite` or `ch.boss` to point to the monster's ID.
4. Add pixel art frames in [`apps/web/src/art/monsters/`](file:///Users/bao/taskbar-hero/apps/web/src/art/monsters/) conforming to `MonsterArt`:
   - Canvas size ≤ 20px (regular), ≤ 28px (elite), or ≤ 56px (boss).
   - Provide required animations: `walk`, `hit`, `defeat` for regular/elite; `idle`, `windup`, `attack`, `hit`, `defeat` for boss.
   - Character matrices must define outline character `k`, omit `.`, and stand on the bottom row.
5. Regenerate documentation:
   ```bash
   node scripts/gen-content-docs.mjs
   ```
6. Run tests:
   ```bash
   pnpm --filter @taskbar-hero/game-rules test src/v2/content/
   pnpm --filter @taskbar-hero/web test src/art/monsters/
   ```

#### Failure Output on Missed Steps
If `docs/content-v2.md` is not updated after adding a monster:
```
FAIL src/v2/content/docs.gen.test.ts > v2 content docs generator > writes docs/content-v2.md when UPDATE_DOCS=1 and matches disk contents otherwise
AssertionError: expected disk to match generated
- | `mon.fluff.ball` | Fluff Ball | regular | 1x | 1x | 1x | 1x |
```
If a monster's kind does not match its chapter role (e.g. assigning a regular monster to `ch.boss`):
```
chapter ch1: mon.fluff.ball is not a boss
```

### 3. Add a Chest Reward

Chests are nested loot tables composed of probabilistic lines (`chance: 0..1`), unit counts (`count: [min, max]`), and weighted picks (`pick: WeightedEntry<T>[]`).

#### Steps
1. Open [`packages/game-rules/src/v2/content/chests.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/content/chests.ts).
2. Locate `chapterChests(chapter: number)` or create a new loot table in `CHESTS`.
3. Add a reward line to `lines`:
   ```typescript
   // Example: Add a 20% chance of 1 Cat Key to Chapter 4+ first-clear chest:
   if (chapter >= 4) {
     firstChest?.lines.push({
       chance: 0.2,
       count: [1, 1],
       pick: [{ weight: 1, value: { kind: 'material', id: 'catKey', amount: 1 } }],
     });
   }
   ```
4. Reward value conventions:
   - **Fish:** `{ kind: 'fish', amount: n }` where amounts scale by `FISH_UNIT` (10 Fish per unit).
   - **Materials:** `{ kind: 'material', id: MaterialId, amount: n }` referencing valid IDs in `MATERIALS`.
   - **Gear:** `{ kind: 'gear', group: 'main' | 'accessory', rarity: GearRarityId }` (smart loot assigns the slot and weapon bias).
   - **Nested Tables:** `{ table: 'gear.ch1.first.main' }` referencing another registered table key.
5. Verify loot table integrity:
   - Line counts must be non-negative integers with `min <= max`.
   - All pick weights must be positive numbers.
   - Nested tables must exist and cannot form circular dependency loops.
6. Regenerate documentation and run tests:
   ```bash
   node scripts/gen-content-docs.mjs
   pnpm --filter @taskbar-hero/game-rules test src/v2/content/content.test.ts
   pnpm --filter @taskbar-hero/game-rules test src/v2/lootcheck/lootcheck.test.ts
   ```

#### Failure Output on Missed Steps
If a line references an unknown material ID or invalid count range:
```
chest chest.ch4.first line 7: unknown material invalidStone
chest chest.ch4.first line 7: bad count
```
If an existing Chapter 1 chest's drop rates or line counts are modified, [`packages/game-rules/src/v2/content/content.test.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/content/content.test.ts#L66) guards plan numbers:
```
FAIL src/v2/content/content.test.ts > v2 content registry > keeps chapter 1 chests at the plan numbers
AssertionError: expected [ 1, 1, 1, 0.4, 1, 0.5, 1, 0.2 ] to deeply equal [ 1, 1, 1, 0.4, 1, 0.5, 1 ]
```

### 4. Add a Recipe

Equipment crafting guarantees target rarity with randomized bonus lines and level scaled to the player's highest stage. Salvaging returns ~25% of the craft cost.

#### Steps
1. Open [`packages/game-rules/src/v2/content/recipes.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/content/recipes.ts).
2. Add a `RecipeDef` to `RECIPES`:
   ```typescript
   {
     id: 'rcp.mystic',
     rarity: 'epic',
     materials: { yarn: 180, shinyButton: 8, catnipCrystal: 4 },
     fish: 2000,
   }
   ```
3. Update `SALVAGE` if introducing a new rarity tier:
   - Every rarity with a crafting recipe must have an entry in `SALVAGE`.
   - **Anti-infinite loop constraint:** `salvage.materials.yarn` MUST be strictly less than `recipe.materials.yarn`.
4. Material checks in `validateContent()`:
   - `id` must match `STORED_ID`.
   - `rarity` must exist in `GEAR_RARITY_IDS`.
   - All material keys must exist in `MATERIALS` (`yarn`, `fluffTuft`, `shinyButton`, `catnipCrystal`, `starlightScale`, `moonPearl`, `catKey`), with quantity ≥ 1.
   - `fish` cost must be an integer ≥ 0.
5. Regenerate documentation and run tests:
   ```bash
   node scripts/gen-content-docs.mjs
   pnpm --filter @taskbar-hero/game-rules test src/v2/content/
   pnpm --filter @taskbar-hero/game-rules test src/v2/forge/
   ```

#### Failure Output on Missed Steps
If salvage returns as much or more Yarn than crafting costs:
```
salvage epic: returns as much Yarn as crafting costs
```
If `docs/content-v2.md` has not been updated:
```
FAIL src/v2/content/docs.gen.test.ts > v2 content docs generator > writes docs/content-v2.md when UPDATE_DOCS=1 and matches disk contents otherwise
AssertionError: expected disk to match generated
- | `rcp.mystic` | `epic` | 2000 | 180 `yarn`, 8 `shinyButton`, 4 `catnipCrystal` |
```

### 5. Add a Class

Adding a new cat hero class is an end-to-end change spanning game rules, combat simulation, rig animations, paperdoll visuals, and API definitions.

#### Complete List of Files to Touch
1. [`packages/game-rules/src/v2/content/classes.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/content/classes.ts):
   - Add class ID to `CLASS_IDS` and `ClassId` type.
   - If introducing a new weapon type: add to `WEAPON_TYPE_IDS` and define its `WeaponProfile` in `WEAPON_TYPES` (windup, hit timings, projectile speed).
   - If introducing a new passive: extend `ClassPassive` union.
   - Add `ClassDef` to `CLASSES` (specifying multipliers, base crit, base dodge, passive parameters, and starter weapon).
2. [`packages/game-rules/src/v2/content/items.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/content/items.ts):
   - If introducing a new weapon type: define weapons for all 5 rarities in `WEAPON_NAMES`. The starter weapon in `classes.ts` must reference the Common weapon (`wpn.<weaponType>.<commonSuffix>`).
3. [`packages/game-rules/src/v2/combat/stats.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/combat/stats.ts):
   - Add passive logic to `passiveDamageMultiplier(classId)` so DPS and power ratings compute correctly.
4. [`packages/game-rules/src/v2/combat/boss.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/combat/boss.ts) & [`fight.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/combat/fight.ts):

5. [`apps/web/src/game/rig/types.ts`](file:///Users/bao/taskbar-hero/apps/web/src/game/rig/types.ts):
   - Add the class ID to `ClassId` and `CLASS_IDS` (and `WeaponType` / `WEAPON_TYPES` if applicable).

7. [`apps/web/src/game/rig/poses.ts`](file:///Users/bao/taskbar-hero/apps/web/src/game/rig/poses.ts):

### 6. Add a Chapter

Chapters sequence game progression, scaling monster health and damage, assigning backgrounds, and dispensing chapter chests.

#### Steps
1. Open [`packages/game-rules/src/v2/content/chapters.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/content/chapters.ts):
   - Append chapter display name to `NAMES` (e.g. `'Attic'`).
   - Append background asset key to `BACKGROUNDS` (e.g. `'attic'`).
   - `CHAPTERS` automatically constructs chapter index `i + 1`, chest IDs (`chest.ch<N>.first`, `chest.ch<N>.repeat`), and gathers monsters.
2. Open [`packages/game-rules/src/v2/content/monsters.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/content/monsters.ts):
   - Add a chapter roster entry to `ROSTER`:
     ```typescript
     [6, ['Cobweb Spider', 'Old Trunk', 'Dust Ghost'], 'Clockwork Owl', 'Shadow Dragon']
     ```
   - Must contain exactly 3 regular monsters, 1 elite, and 1 boss.
3. Open [`packages/game-rules/src/v2/content/chests.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/content/chests.ts):
   - Update `CHESTS` export to include the new chapter index in the mapping list:
     ```typescript
     export const CHESTS: LootRegistry<ChestReward> = Object.fromEntries(
       [1, 2, 3, 4, 5, 6].flatMap(chapterChests).map((t) => [t.id, t]),
     );
     ```
4. Open [`packages/game-rules/src/v2/content/items.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/content/items.ts):
   - **Crucial Drop Coverage Rule:** `validateContent()` requires that **every chapter can drop every slot × rarity (and every weapon type × rarity)**.
   - Update `ALL_CHAPTERS = [1, 2, 3, 4, 5, 6] as const;` so weapons and accessories drop in chapter 6.
   - Update armor set drop chapters (e.g. `ARMOR_SETS`: ensure `dropChapters` for `moon` or a new endgame armor set includes `6`) so helmet, armor, gloves, and boots of all 5 rarities can drop in Chapter 6.
5. Create chapter monster art in [`apps/web/src/art/monsters/`](file:///Users/bao/taskbar-hero/apps/web/src/art/monsters/).
6. Regenerate documentation:
   ```bash
   node scripts/gen-content-docs.mjs
   ```
7. Update test assertions in [`packages/game-rules/src/v2/content/content.test.ts`](file:///Users/bao/taskbar-hero/packages/game-rules/src/v2/content/content.test.ts):
   - Update `expect(CHAPTERS).toHaveLength(5)` to `6`.
   - Update `expect(CHAPTERS.map((c) => c.killsPerRound))` array.

#### Failure Output on Missed Steps
If you add Chapter 6 to `chapters.ts` without providing monsters, chests, or item drop coverage, `validateContent()` catches every deficiency simultaneously:
```
chapter ch6: no regular monsters
chapter ch6: monster  not found
chapter ch6: chest chest.ch6.first not found
chapter ch6: chest chest.ch6.repeat not found
chapter ch6: no common helmet drops
chapter ch6: no common armor drops
chapter ch6: no common sword drops
... (80 item drop coverage errors across all slots, weapon types, and rarities)
```

## Verification Commands

Run these checks locally before opening a pull request:

```bash
# 1. Regenerate content reference documentation if content changed:
node scripts/gen-content-docs.mjs

# 2. Verify game rules content and forge logic:
pnpm --filter @taskbar-hero/game-rules test

# 3. Verify character rig, monster art, and UI frames:
pnpm --filter @taskbar-hero/web test

# 4. Run workspace-wide typechecking, linting, and full tests:
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```
