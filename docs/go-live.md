# Going live (Edge Functions)

For the current release order, pending migration list, go/no-go gates and rollback, use the
[Cat RPG v2 cut-over checklist](cutover-v2.md). The base v2 schema was applied live on 26 Oct and
integrity on 27 Oct; newer migrations still need owner confirmation. Never assume all migrations
are live just because they are committed.

There are **18 Edge Functions**: nine classic/shared and nine `v2-*`. Each function's `deno.json`
import map is generated by `pnpm gen:deno`; commit the result and check for drift. For this release,
use the user's manual deployment command in [cut-over](cutover-v2.md#3-deploy-the-verified-functions-user-only)
after schema confirmation and `node scripts/check-deno-imports.mjs`. This page describes one-time setup.

Never paste any of these values into git, an issue, a PR or a chat.

## 1. Deployment setup (owner only)

1. Create a personal access token at https://supabase.com/dashboard/account/tokens (name it `github-deploy`).
2. In GitHub: repo **Settings > Secrets and variables > Actions > New repository secret**, name `SUPABASE_ACCESS_TOKEN`, value the token.
3. The existing workflow deploys changed function bundles on `main` when configured. Do not dispatch Actions for this release; use the manual command linked above. Without the secret the workflow shows a "Deploy skipped" notice.

Functions are deployed with `--no-verify-jwt` (also set in `supabase/config.toml`): the platform gateway does not check the `Authorization` header, because our functions verify our own session JWT themselves.

## 2. Function secrets (Supabase dashboard)

Supabase dashboard > your project > **Edge Functions > Secrets** (or `supabase secrets set --project-ref qoalewtxflagoprrxrgh NAME=value`). New values apply to the next request; no redeploy needed.

| Secret | What to put | Used by |
| --- | --- | --- |
| `AUTH_JWT_SECRET` | Random, at least 32 bytes: `openssl rand -base64 48`. Signs and checks the session JWT. Changing it signs everyone out. | all 18 |
| `GAME_SEED_SECRET` | Random: `openssl rand -base64 48`. Keys the idle-drop, boss-fight and Relic rarity seeds. Optional (falls back to `AUTH_JWT_SECRET`), but set it so the two can change independently. | classic and v2 game functions |
| `SIWE_DOMAIN` | The production host, no scheme or path, e.g. `taskbarhero-eight.vercel.app` (the live site). Must equal `window.location.host` of the site players sign in on. | auth-nonce, auth-verify |
| `SIWE_ALLOWED_ORIGIN` | Comma list of exact origins allowed by CORS, e.g. `https://taskbarhero-eight.vercel.app,http://localhost:5173`. Unset means browsers are blocked. | all 18 |
| `VOUCHER_SIGNER_PRIVATE_KEY` | The voucher signer's private key (`0x` + 64 hex). Its address must equal `signer()` on the deployed RelicNFT. Use a dedicated key that holds no funds; never reuse the deployer key. Unset or malformed: `relic-forge` answers 500 `server_error` and spends nothing. | classic and v2 Relic functions |
| `FUJI_RPC_URL` | Optional. Fuji C-Chain RPC used to check mint receipts and `usedNonces`. Defaults to `https://api.avax-test.network/ext/bc/C/rpc`. | classic and v2 game functions |

Provided by the platform, do not set: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (Supabase refuses custom secrets starting with `SUPABASE_`). The code also reads `SUPABASE_JWT_SECRET` before `AUTH_JWT_SECRET`; the platform does not set it, so leave it unset.

Note: `AUTH_JWT_SECRET` is our own key, not the project's JWT secret, so the session token works with our Edge Functions only, not with direct PostgREST queries. The web client uses only the functions.

Sign-in with `localhost:5173` against the live functions needs `SIWE_DOMAIN=localhost:5173`, so local testing against production is limited to the game calls; use a local stack for sign-in.

## 3. Web app (Vercel)

Vercel project **web** > Settings > Environment Variables (Production), then redeploy. Vercel builds only the `main` branch (`apps/web/vercel.json` skips every other branch), so every merge to `main` deploys the site, and pull requests get no preview:

- `VITE_GAME_V2` = `1` for v2, `0` for classic. This is a build-time switch: redeploy after changing it.
- `VITE_SUPABASE_URL` = `https://qoalewtxflagoprrxrgh.supabase.co`
- `VITE_SUPABASE_ANON_KEY` = the project's anon/publishable key (dashboard > Project Settings > API). Safe to expose.

## 4. Smoke test

For the unsigned v2 probes run `node scripts/check-live.mjs --v2`; see the
[cut-over health gate](cutover-v2.md#4-set-the-web-switch-and-check-the-release) for exact statuses and
the authentication-before-body limitation. These probes do not prove signed-in gameplay or the
live schema. The legacy nonce probe below issues a challenge. Replace the origin with your production origin.

```sh
ORIGIN=https://taskbarhero-eight.vercel.app
FN=https://qoalewtxflagoprrxrgh.supabase.co/functions/v1

# A nonce, and the CORS header echoing your origin.
curl -si -X POST "$FN/auth-nonce" -H "Origin: $ORIGIN" | grep -iE '^HTTP|access-control-allow-origin|nonce'
# expect: HTTP/2 200, access-control-allow-origin: <your origin>, {"nonce":"<32 hex chars>"}

# Browser preflight.
curl -si -X OPTIONS "$FN/game-state" -H "Origin: $ORIGIN" -H "Access-Control-Request-Method: POST" | grep -iE '^HTTP|access-control-allow-origin'
# expect: HTTP/2 204 and the same header

# The game functions run and refuse a missing session (proves --no-verify-jwt took effect).
curl -s -X POST "$FN/game-state" -H "Origin: $ORIGIN"
# expect: {"error":"unauthenticated"}. A gateway error about a missing authorization header means verify_jwt is still on.
```

If the CORS header is missing, `SIWE_ALLOWED_ORIGIN` does not contain that exact origin (scheme, host and port must match). A 500 `{"error":"internal_error"}` from `auth-nonce` usually means a missing secret; see **Edge Functions > Logs** in the dashboard.
