# Browser test stability

Run from `apps/web` with `npx -y pnpm@10.28.0 test:e2e`. No prebuilt site is required:
both preview servers build fresh, with empty Supabase URL/key for local demo saves.
The classic build explicitly sets VITE_GAME_V2=0; the v2 build sets VITE_GAME_V2=1.
Both servers have a 120-second startup limit and strict ports. Unknown existing
servers are rejected so an old preview cannot silently supply stale assets.

## Projects and new specs

- classic: top-level e2e specs, classic build.
- stage-layout: layout and ui specs, v2 build.
- v2-loop: gameplay loop specs, v2 build.

Put new UI specs in `apps/web/e2e/ui/` and import test/expect from
the shared `apps/web/e2e/support/test.ts` fixture. No baseURL override is needed. Directory-based discovery also
routes plain Playwright imports to v2. The shared fixture checks file/project
assignment and the shared expected URL before each test, then checks the first
normal page for the v2 marker (or its absence in classic). The arena developer preview renders outside
StageLayout, so its project and URL are checked but it has no shell-marker check.

## Ports and concurrent runs

Default ports are 4173 (classic) and 4174 (v2). For an independent run:

```sh
E2E_PORT_CLASSIC=4273 E2E_PORT_V2=4274 npx -y pnpm@10.28.0 test:e2e
```

Ports must be distinct integers between 1 and 65535. Each server's preview URL,
project URL, build directory, and test output use those shared values. Builds
live in port-specific subdirectories of dist and dist-v2; test artifacts live
under test-results by port pair. Concurrent runs need four distinct ports. Avoid
running a separate root build while browser suites build in the same checkout.
Screenshot runs that target the same report should run sequentially.

## Interrupted runs and orphan previews

Playwright normally stops its server process groups. If a run is interrupted,
inspect the listeners, their command, and their working directory first:

```sh
lsof -nP -iTCP:4173 -iTCP:4174 -sTCP:LISTEN
ps -p <pid> -o pid,ppid,command
lsof -a -p <pid> -d cwd
kill <owned-pid>
```

Substitute overridden ports as appropriate. Stop only processes belonging to
your run. On a machine dedicated to this checkout, the broad cleanup command is
`pkill -f "vite preview" || true`; it also stops previews in other worktrees.
After stopping leftovers, rerun normally. Do not enable reuseExistingServer to
mask the collision. Alternatively choose another unused port pair.

## Evidence without report churn

Disk screenshots require SCREENSHOTS=1. Vignette tests still capture pixels in
memory during ordinary runs, so their measurement remains meaningful without
rewriting report files. The former screenshot-only U4 test now always validates
its views and only writes PNGs when requested.

S1 evidence is generated by the UI s1-infra spec. Six contact sheets show main,
Forge, and Boss at each required viewport/color scheme, keeping the mission
within the 16-PNG budget. Each panel is a native viewport capture. Run:

```sh
SCREENSHOTS=1 npx -y pnpm@10.28.0 test:e2e e2e/ui/s1-infra.spec.ts --project=stage-layout
npx -y pnpm@10.28.0 test:e2e
git status --short reports/
```

The normal run must leave other missions' report files untouched.

# Test-suite stability

Measured 2026-10-24 on `main` (commit `40ea4d5`) on a 4-core cloud container. "Plain" means `pnpm test` alone; "under load" means `pnpm test` while two `pnpm build` runs execute at the same time (CI-like contention).

## Findings

| Run | Before the fix | After the fix |
| --- | --- | --- |
| Plain, 4 runs | 4 of 4 passed, 46.0 to 47.3 s | 4 of 4 passed, 37.3 to 39.2 s |
| Under load, 4 runs | **0 of 4 passed**, 50.8 to 54.0 s | 4 of 4 passed, 54.3 to 57.9 s |

Every failure before the fix was `Error: Hook timed out in 10000ms` in the `beforeAll` of supabase test files (run 1: `auth-wrappers`, `concurrency`, `forge`, `siwe`; run 2 and 3: `concurrency`, `siwe`; run 4: `siwe`). No assertion ever failed: no test was wrong, the setup was too slow. The cause is that every test file migrated its own fresh PGlite (about 3 s alone, much longer when twelve files do it at once on four cores) and vitest's default hook timeout is 10 s. This also explains the single suite-level failure seen once while developing `malformed.test.ts` (#90).

The web, game-rules, auth, chain and api-contract packages never failed in any of the 16 runs.

## What changed (tests only)

- `supabase/tests/global-setup.ts` (new): migrates PGlite **once per run** and dumps the data directory to a temp file. `migratedDb()` in `src/game-db.ts` now starts each file from that dump (about 0.5 s) and falls back to migrating from scratch if it is not available. A migration error now fails the whole run in one place.
- `schema.test.ts`, `siwe.test.ts` and `consistency.test.ts` used their own copy of the migrate loop; they now use `migratedDb()`.
- `supabase/tests/vitest.config.ts`: `hookTimeout` 60 s and `testTimeout` 30 s, so a slow machine produces a slow run, not a red one.
- No sleeps were added, no assertions loosened, no test skipped, nothing outside `supabase/tests` touched.

## Timing

Whole `pnpm test` (plain): about 47 s before, about 38 s after. The supabase package went from 28.8 s to 19.4 s; the web package takes about 15 s and is unchanged.

Slowest files (test time reported by vitest, after the fix):

| Package | File | Time |
| --- | --- | --- |
| supabase | `malformed.test.ts` | 3.8 s (about 130 requests, each followed by a full-database dump) |
| supabase | `concurrency.test.ts` | 2.0 s |
| supabase | `forge.test.ts` | 1.5 s |
| supabase | `rls.test.ts` | 1.0 s |
| web | `inventory/InventoryTab.test.tsx` | 1.3 s |
| web | `boss/BossTab.test.tsx`, `forge/ForgeTab.test.tsx` | 1.1 s each |

Most of the web package's time is the jsdom environment starting for each of its 23 files (about 60% of its wall time), not the tests.

## Notes

- Under load the suite takes 54 to 58 s versus 38 s plain. That slowdown is real CPU contention and is expected.
- Nothing in these runs needed a retry. If a hook timeout ever appears again, check whether the machine is out of memory first: the template dump is about 40 MB and each worker holds its own PGlite copy.

## F2: local server mode

Run the real server transport journeys from the repository root with one command:

```sh
npx -y pnpm@10.28.0 --filter @taskbar-hero/web test:e2e --project=v2-server --workers=1
```

For migration → flag-on build → the same journeys → SQL rollback, use:

```sh
node scripts/rehearse-cutover.mjs
```

The v2-server project adds ports 4175 (web) and 4176 (API); existing classic/demo ports
remain 4173/4174. E2E_PORT_SERVER and E2E_PORT_API override the new ports. All four must
differ; unknown listeners are refused, and no existing server is reused. Only one browser
suite should run at a time per port set. Inspect listener PIDs and cwd before terminating
owned leftovers. The server build is isolated under apps/web/dist/v2-server/ and ignores
.env files. No dependency or real secret is needed beyond the frozen workspace install.

The browser stores a short-lived test session in sessionStorage, never a demo save.
Fixtures seed catalog-based preconditions into real migrated SQL; all tested actions use
SupabaseGameApiV2 → HTTP → handlerV2/routesV2 → pgliteV2Store → SQL. The Node adapter uses
the existing token verifier with a fresh in-memory signing secret and ephemeral voucher
key. It does not instantiate the hosted Supabase client or a remote chain reader. The local
controls have no CORS, reject browser Origin headers, and bind only to 127.0.0.1.

Each journey owns a distinct SQL player. Browser timers are controlled separately from a
per-player server clock so claims do not depend on wall-clock sleeps. Two-tab claims wait
at a network barrier until both have been sent, then overlap real handlers; assertions
check one progress revision and the exact credited reward. Retry testing drops the response
after SQL commit, then checks equal request IDs, one action receipt, one UUID in the UI and
one recipe charge. Equip best counts each changed slot's mutation and asserts no redundant
state reads. Boss tests assert concealment, press Skip fight, then inspect the result.

Visibility events are synthetic in headless Chromium; they exercise real listeners and the
header SyncStatus. PGlite serializes SQL on one connection, so production lock scheduling
is not measured. The session entry point is test-only; real SIWE browser signing and hosted
Deno/REST wiring are not covered. The walletless Relic journey verifies the existing UI
refusal and zero request/spend. See [cut-over rehearsal](cutover-v2.md#rehearsal-local-only-f2)
for the missing manual-rollback file and conditional Founder batch step.

F2_EXTERNAL_SERVER=1 and F2_SERVER_PREBUILT=1 are internal rehearsal handoff flags: the
script starts the API on the restored snapshot and supplies the just-built web output.
Ordinary runs should leave both unset so Playwright owns all startup and cleanup.

## Both mission desktop sizes

`E2E_VIEWPORT=1280x720 pnpm test:e2e` and `E2E_VIEWPORT=1600x900 pnpm test:e2e`
(from apps/web) run the same complete project set with each requested default
viewport. The default remains 1280x720. Explicit per-test responsive-size cases
remain intact. Any other E2E_VIEWPORT value fails before servers start. Use the
existing four E2E_PORT variables when runs overlap; output directories stay
port-isolated. Run one worker for repeated performance-sensitive cases.

Ordinary tests keep screenshots in memory when measuring encoded byte budgets;
PNG report writes require SCREENSHOTS=1. The F3 and error-notice writers honor
SCREENSHOT_DIR. F3/G1/G3 metrics go into Playwright output unless REPORT_DIR is
explicitly set, so reruns do not rewrite historical tracked reports.
