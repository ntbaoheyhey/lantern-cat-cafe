# C1: client-side block guards (offline only)

## Added
- `packages/game-rules/src/v2/state/guards.ts`: pure pre-checks `guardChooseClass`, `guardEquip`, `guardCraft`,
  `guardSalvage`, `guardLock`, `guardRelicForge`, `guardBoss`, `guardClaim`. Each runs the same pure rule the
  v2 Edge Functions run, so the refusal code is the server's code (`no_class`, `stale`, `wrong_slot`, `slot_locked`,
  `wrong_weapon`, `not_owner`, `not_enough`, `bag_full`, `equipped`, `locked`, `forge_blocked`, `cooldown`,
  `not_reached`, `no_key`, `invalid_request`). Exported from `v2/state/index.ts`. No UI wiring.
- `guardClaim` returns credited seconds (0 inside the 10 s minimum or on a rewound clock, capped at 8 h),
  `clockRewound` and `capped`.
- `guards.test.ts` (16 tests): every guard code is in the server HTTP table (`supabase/functions/_shared/v2/http.ts`,
  read from disk); the minimum claim interval equals the server constant; per-action refusals; offline reward:
  8 h cap, 30 and 31 days equal 8 h, negative/NaN elapsed pays nothing, flat above the cap, reward by current stage.
