# C0: acceptance checks and evidence retention

Question: How do we enforce the new scope, clock, audio and learning rules without hiding genuine regressions or growing the capture tool?

## How professionals handle this
- A measurement needs an explicit clock and origin; a render completion timestamp is not an action start (C0-clock).
- The audio stream has a separate time system; align recorded onsets with visual events rather than equating cue scheduling with audible contact (C0-audio-clock).
- Attribute a failing assertion to its owning feature; retain already completed feature checks as regressions (C0-experiment, user section 3.4).
- Preserve measured observations even when the interpretation changes; do not overwrite old failures with an assumed pass (C0-local).
- Missing measurements, missing artifacts or mutated hashes remain OPEN; a future feature does not become a present failure (C0-experiment).
- Ignore patterns affect untracked files; already tracked raw assets need explicit index removal (C0-ignore, C0-rm).
- Keep the local original and a small reviewable summary, with stable hashes and replay commands (C0-rm, C0-video).
- Use positive and negative test cases for every acceptance rule, including incomplete matrices (C0-test).
- Finalize capture output before probing duration, dimensions and contents (C0-video).

## Sources
- C0-clock [formal]: https://www.w3.org/TR/hr-time-3/ — Measure durations with monotonic time; translate clock origins explicitly instead of subtracting mixed render timestamps.
- C0-audio-clock [formal]: https://www.w3.org/TR/webaudio/ — Audio scheduled time is relative to AudioContext.currentTime, which need not match other clocks.
- C0-ignore [doc]: https://git-scm.com/docs/gitignore — Ignore rules do not remove tracked artifacts from the index.
- C0-rm [doc]: https://git-scm.com/docs/git-rm — Use explicit paths with rm --cached to preserve local evidence while removing it from future commits.
- C0-test [doc]: https://nodejs.org/api/test.html — Assert both positive and negative examples; awaited tests report rejected promises as failures.
- C0-video [doc]: https://playwright.dev/docs/videos — Finalize captures before examining them; confirm explicit viewport and encoded dimensions.
- C0-experiment [experiment]: tools/v3craft-lab/c0/results.json — 54 future craft rows add OPENs to Q1; all existing ultimate plans are exactly 2200/1100 ms but inferred overlaps reach 6.30 ms.
- C0-local [local]: reports/v3-feel/REVIEW/Q1/REVIEW.md — Honest old frame observations identify true later-item defects; preserve these observations while separating ownership.

## Chosen method
Keep one scoped acceptance contract with owned gates and explicit completed-item regression selection. Timing gates require schedule-labelled observations plus a separate <=33 ms video-confirmation check. Audio uses onsets, cue mapping, spectral type, voice concurrency, LUFS and true peak; human listening is a user review task, never a machine acceptance prerequisite. Add strict learning and craft-time validators with bad-data tests. Keep the existing recorder only if its single isolated trial succeeds; no new recording features.
Reject all-row Q1 gating (scope bleed), post-draw inferred scheduling (mixes latency into starts), schedule-only acceptance (cannot prove pixels), ignored-but-still-tracked raw files (no size benefit), and self-declared timing totals (no real start/end intervals).

## Quality judgment
C0.learn: >=6 sources, >=1 formal/paper, >=3 internet docs, >=1 own experiment with real output, nonempty learning record, cited by the build commit. C0 policy tests need a fake PASS and FAIL for each changed rule. New Q2 number, Q3 craft-time/rung-one/washout and Q5 objective-audio rules retain the user thresholds. Existing evidence remains unaccepted until Q1 applies the new method and watches the relevant video.
