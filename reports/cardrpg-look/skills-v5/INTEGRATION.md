# Skills V5 V0 presentation integration

Base: `598fd8019e62b7203dcfac4033f74bb64ba0dac5`, the B2 V6 branch tip after the report's `f4cd0da0b` checkpoint. The extra tip commit is handoff documentation. V0 does not adopt A5 or Skills V5 rules.

- Adopt the B-owned source changes and SVG archives together. Keep `lookV2` as the outer gate; `LEGACY_CARD_STATUS_LOOKS` retains the six OFF cues. No rules, balance, dependencies or saves change.
- `StatusBadges` reads live actor statuses and `STATUS_BY_ID`. Adding a rules status requires its display name, original icon, body/apply/tick/expiry look and a passing catalog-coverage test. Labels intentionally retain the existing tooltip rules while using the approved plain-English vocabulary.
- `statusPresentation(plan, battle.log)` matches existing adapter sequence numbers to resolved source logs once per plan. Apply/tick/expiry and Crumb Burst are derived from real logs, never inferred from a selected skill. Unmatched logs use legacy presentation. No event or plan is mutated.
- Target visuals use 70ms offsets in log order inside the existing action. The action duration delta is 0ms; direct/DoT labels stay separate. Crumb Burst words last 500ms and anchor above each projected target; V0.1 reserves their space before placing HP cards, then avoids other words and the moment card within the stage.
- Carry `SceneView.cardPresentation`, structured `cardStatuses`, pooled body height and live crown anchors together. Face masks, effect/light pools and lazy renderer loading remain in place. Sixteen statuses can coexist, but four HUD badges plus +N are the readable summary. V0.1 uses distinct framed20px icons (16px at1024), camera-facing countable side flames and .76 Warm/Glaze halos; crown marks may bypass only the empty-air portion of the circular face margin above the complete model.
- Existing battle events-v4 v1 remain supported; unknown battle versions retain the inherited legacy fallback. Do not mistake earned-reveal v2 support for a Skills V5 battle adapter. Earned reveal API, phase <=400ms and finish <=800ms are untouched.
- Bleed/Bitter and new reactions require lane A's published v2 fixture before V3. Needed fields: status-applied `{statusId,stacks,sourceId,targetId}`, status-tick `{statusId,amount}` with unambiguous bearer/source context, reaction `{reactionId,primerIds[],targets[]}`, multi-hit `{skillId,targets[] in order,shape}`; retain event ordering and action/round identity.

The offline demo's Status guide offers clearly labelled presentation previews. The six paired shots deliberately stage statuses and rule-resolved row/detonation actions; the videos use an ordinary chapter-1 battle at x1 with no injected actions. Human status-recognition acceptance is not measured.

Measurements bind to the artifact SHA and source hashes in `RESULTS.json` and `source-audit.json`. Earlier overlap, crown clipping and harness failures are retained in iteration/diagnostic receipts and are not reported as passing delivery samples. No merge or deployment is part of this handoff.

## V3 · Published S4 fixture adapter

Lane A published the fixture in draft412 on `codex/cardrpg-v5a-s4-2026-11-09`; B fetched it read-only. The exact parsed object is archived in `tools/cardrpg-look/skills-v5/v3-source.json`, with source provenance in `v3/FIXTURE.json`. It supplies the two new status looks, four reactions and splash/multi-hit/bounce previews in `docs/cardrpg-look/v5.html`.

- The discriminator is **per-event `version:2`**; the battle container remains `v4.version:1`. `kind`, `sequence`, `actionId`, `stage` and `logIndex` identify and order the event. `reaction.targetId` is the primer/callout anchor, while `targets` contains affected destinations. A repeated target in `multi-hit.targets` remains a separate 70ms landing; never deduplicate or reroll it.
- `applyV5Presentation` accepts immutable before/after status snapshots. Consumed primers receive an expiry beat; Bitter labels use the before snapshot even when the action removes it. Unknown or malformed event versions return the legacy presentation. Reaction words last400–500ms within the existing action; no rule or action-clock changes.
- `v5SourceForPlan` provides the versioned adapter boundary for later integration; live `skillsV5` ON gameplay has **not** been integrated or validated here. The fixture viewer renders the published snapshots and logs, and its film is explicitly labelled recorded playback. It does not call V5 combat resolution or adopt Lane A's rule files.
- Keep `lookV2` as the outer gate and preserve earned-reveal/phase/finish APIs. The new SVG paths and pooled effect shapes have provenance in `assets/provenance/look.md`. For live adoption, pass the real action's before/after snapshots with the versioned events, then validate real battles in the later integration step.
