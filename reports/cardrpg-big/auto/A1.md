# A1 automatic controller
REFERENCE: packages/game-rules/src/cardrpg/depth/policies.ts, battle.ts, policies.test.ts

The controller evaluates one legal action at a time using the existing battle engine and state value. Urgent healing and removing an enemy receive explicit weight so the action has a visible purpose.
One-action evaluation bounds the work per turn. Stable skill/target ordering resolves ties, and preview copies preserve the live RNG and actors.

## Matched campaign simulations
REFERENCE: reports/cardrpg-big/sim/auto-before.json, auto-before-heldout.json, auto-a1.json, auto-a1-heldout.json

Each cell uses 50 seeds and the existing safe route bot, with starter cats and equipment. Training seeds are 1–50. Held-out seeds are 10001–10050. Chapter access is unlocked in the fixture. These are whole seven-node campaigns, including the boss.

| 1 | 66% | 56% | 74% | 44% |

Chapter 1 regresses by 10 percentage points on training and 30 on held-out seeds. That remains a balance concern for phase I. The controller has not been retuned against held-out results. Chapters 2 and 3 improve in this sample. No manual-versus-auto performance target is used.

## Tests and scope
REFERENCE: reports/cardrpg-big/validation/a1-controller-tests.log, packages/game-rules/src/cardrpg/depth/policies.test.ts

Nineteen focused tests pass. Tests check no preview mutation, repeatable choices, low-health healing, a reachable finishing hit, a useful ultimate and full watched/skip/replay equality over five seeds.
Action log descriptions capture pre-action health. The replay uses the same action function and produces the same log. Existing combat resolution, save shape, rewards and live game configuration have no edits in this change.

The first weak-target test exposed that inherited health scoring undervalued a finishing hit. A fixed value for removing future enemy turns was added before any A1 campaign results were inspected.
