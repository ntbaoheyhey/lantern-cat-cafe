# G0 rule and interface audit
REFERENCE: G0-AUDIT.md; packages/game-rules/src/cardrpg/depth/{battle,policies,equipment,state,run,save,bridge}.ts; apps/web/src/game/cardrpg/depth/{Encounter,Pages,TeamCollection,CollectibleDesigns}.tsx.

Read against the unchanged delivery rules. These are source observations and design hypotheses, not newly simulated causal proofs. Fresh baseline receipts remain the numerical authority.

| Observation in current source | Player consequence / v4 requirement |
|---|---|
| Enemy stats scale by chapter and tutorial status; they do not use the team's progression band. | Stronger accounts eventually overwhelm fixed content. Add a visible intended challenge band, preserve easier completed routes and compare tiers on the band's intended content. Never secretly scale difficulty with equipped gear. |
| Complete unlocked skill kits enter combat, including level-six ultimates. | Keep automatic complete kits; isolate the unlock's contribution in balance fixtures. Do not restore choose-three controls. |
| Automatic policy evaluates every legal skill/target via a one-action preview. | Standing plans must modify this deterministic selection before combat. Preview state must not mutate event streams or issuance/economy data. |
| Energy, break, and flavour advantages still affect the legacy resolver. | The user rejects these systems in v4. Suppressing labels is insufficient: ON must remove their effects, legacy charms/affixes need an explicit replacement mapping, and OFF must retain the existing resolver exactly. |
| Boss result checks only whether all enemies are dead. Boss summons have independent HP. | Retire linked adds on the boss's defeat and emit one explicit ending event. The G0 day-seven observation includes 22.015 seconds of cleanup. |
| Set thresholds are two/four equipped pieces; several effects refer to energy, break, or a row-swap skill. | Preserve set identities while giving every set a useful, measurable v4 job. Show the condition and behavior change in equipment comparison. |
| Single-item display score counts only HP/attack/defense. Effects include revive prevention, shielding, status changes, and AI access to rear targets. | A small score share is not evidence of a small paired outcome gain. Include readable utility, score calibration and heldout paired comparisons. |
| `craftGear` and `dropGear` append to depth gear without a capacity rule; gacha imports legacy items into a separate depth list. | One capacity rule must cover all acquisition routes. Craft/draw rejection must occur before spending; mandatory route drops need disclosed conversion. Avoid double-counting mirrored legacy/depth records. |
| `equipGear` moves one instance away from its previous owner. Presets currently store teams rather than full gear/tactics. | Full saved loadouts reference instances, preview transfers and missing pieces, and apply atomically. A missing item must not partially unequip the team. |
| Collectible reservations increment counters in one editable save. | A pure sequential ledger can enforce caps within one authority and reject stale revisions, replays, and invalid effort claims. It cannot enforce a global cap across copied saves. Display that boundary and specify the future authoritative issuer. |
| Save checksum detects corruption; safe-tree validation and enemy snapshots preserve older battles. | Bump the save envelope and migrate only missing v4 fields. Do not turn an already-started legacy battle into v4 mid-replay. Optional v4 data must not change OFF battle serialization. |
| Prepare's enemy information is below the team cards; five alternate-seed fights produce its difficulty label. | Put opponent role and intent beside editable rows and tactics. A five-fight estimate is a hint, not a calibrated success probability. Clearly separate a build hint from a measured heldout balance claim. |
| Idle and daily rewards already have caps, and daily/challenge/run receipts already exist. | Extend these loops with a compact board and permanent milestones. Do not add parallel uncapped reward paths or treat absence as a penalty. Keep protected Fuji bridge code unchanged. |
