# S8: production-like rehearsal and deploy runbook

The work order defines G-REHEARSAL as a **production Vite build served by vite preview with local API and Anvil**, ten complete journeys, boss median >=50FPS at1280x720, <=8MB transferred before the first battle and no development-only path. This is distinct from a public Fuji deployment; no hosted writes or public transactions are performed by SHIP.

## Sources applied

- [S8-RESOURCE-TIMING](https://www.w3.org/TR/resource-timing/): Resource transferSize can be zero for caches or restricted cross-origin resources. Capture a fresh browser profile plus network-level encoded lengths and retain missing-measurement limits.
- [S8-VITE-PREVIEW](https://vite.dev/guide/static-deploy.html): Use vite build then vite preview to test the emitted production bundle locally; preview is not a production hosting server.
- [S8-VITE-ENV](https://vite.dev/guide/env-and-mode.html): VITE variables are embedded in client output at build time. Keep secrets out, distinguish production NODE_ENV from mode, and prevent inherited local environment drift.
- [S8-VERCEL-LIMITS](https://vercel.com/docs/limits): Current Hobby cap is100 deployments/day; Pro is6000. Budget the user deployment under the work order cap; the account plan and remaining quota are not verified.
- [S8-SUPABASE-MIGRATIONS](https://supabase.com/docs/guides/deployment/database-migrations): Review migration history and apply pending files in order with one operator. Installed CLI2.122.0 supports linked flags; do not copy newer remote syntax without verification.
- [S8-SUPABASE-FUNCTIONS](https://supabase.com/docs/guides/functions/deploy): Deploy the required functions after their schema; preserve explicit gateway/auth configuration and avoid pruning unrelated functions.
- [S8-VERCEL-BUILD](https://vercel.com/docs/cli/build): Production local build uses prod environment values; local building is separate from uploading a deployment.
- [S8-VERCEL-PREBUILT](https://vercel.com/docs/cli/deploy): Deploy prebuilt uploads the previously built output; later metadata cannot change embedded environment values.
- [S8-VERCEL-ROLLBACK](https://vercel.com/docs/cli/rollback): Rollback changes the production assignment. Hobby can roll back only to the preceding production deployment; save its URL before publishing.
- [S8-FLAG-COMPARISON](../../../reports/v4-ship/S8/flag-comparison-1.json): Executing the real flag functions: compact demo5/9 features versus explicit flags9/9; empty configuration0/9 and journey disabled. Four features require separate opt-ins and backend prerequisites.

## Measured method comparison

[The experiment](../S8/flag-comparison-1.json) executes the actual `chainFlags` and `shipJourneyEnabled` functions. The convenience demo flag enables 5/9 feature flags; an explicit complete flag set enables 9/9. Both enable the core journey when its own switch is present. An empty configuration enables0/9 and disables the journey. Cosmetics, optional RelicForge, campaign and campaign rewards need separate opt-ins.

Use an explicit table with backend prerequisites for the deploy runbook. The experiment's all-on configuration is a comparison, not approval to activate an undeployed feature. The seven-step Workshop uses the existing economy/item/judge services; optional RelicForge remains off on Fuji without a verified registry address.

For browser measurement, use a new profile and count network encoded data in addition to Resource Timing. Cached or cross-origin zero-byte entries cannot be interpreted as a free download. Compare the development entry with the emitted production entry, then measure the complete production path separately. Do not add `dev=1`, offline mocks or development helper dependencies to make it pass.

The runbook will retain current migration history, finite funding envelopes and signed-voucher expiry. Its public sponsor check requires balance >=1AVAX + pending reservations +0.05AVAX +21000*gasPrice; the existing SQL transaction remains authoritative. Frontend rollback cannot reverse confirmed chain transactions or database writes. Backend shutdown disables issuers first without resetting ledgers.

Learning is complete for preparation; production rehearsal and remote readiness remain unmeasured. S4 development journeys do not close this gate.
