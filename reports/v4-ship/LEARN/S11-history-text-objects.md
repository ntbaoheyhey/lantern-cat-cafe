# S11 unique historical text objects

Read 16 November 2026 before building the study. The original text scanner remains active and untouched; the 25-commit batch diagnosis found 100,727,617 added lines. Repeated patch additions can cause repeated work, but a faster zero-finding run is not coverage evidence.

1. [Git cat-file](https://git-scm.com/docs/git-cat-file): batch object reads return type, size and unfiltered bytes. Verify object identity and length before any scan; do not use textconv or checkout normalization.
2. [Git ls-tree](https://git-scm.com/docs/git-ls-tree): NUL-delimited recursive tree entries preserve names. Reuse the independently verified frozen inventory of all historical path/object mappings, not one name per blob.
3. [Git rev-list](https://git-scm.com/docs/git-rev-list#Documentation/git-rev-list.txt---object-names): object names are hints and only one may be shown for an object. Unique object traversal cannot replace filename-aware checks or account for later references by itself.
4. [RFC 3629](https://www.rfc-editor.org/rfc/rfc3629.txt), formal Internet Standard: validate UTF-8 strictly. Non-UTF-8 or NUL-containing inputs remain explicitly outside this raw-text experiment; extensions do not prove text coverage.
5. [Gitleaks 8.30.1 stdin command](https://github.com/gitleaks/gitleaks/blob/v8.30.1/cmd/stdin.go): stdin uses the File source. It does not supply the original repository filename.
6. [Gitleaks 8.30.1 File source](https://github.com/gitleaks/gitleaks/blob/v8.30.1/sources/file.go): nominal 100 KB reads, safe-boundary extension and application MIME filtering can change which fragments reach the detector. Compare controlled public invalid fixtures for boundary loss and filtering; do not interpret their absence as a clean scan.
7. [Gitleaks 8.30.1 Git source](https://github.com/gitleaks/gitleaks/blob/v8.30.1/sources/git.go): text diff additions are sent as fragments; non-archive binary diffs are skipped. A root commit with each text object once can use this existing path without repeated historical additions. Independently verify every synthetic patch as one complete addition with original bytes, line count and EOF before trusting the scanner result.
8. [Gitleaks detector](https://github.com/gitleaks/gitleaks/blob/v8.30.1/detect/detect.go) and [pinned default rules](https://github.com/gitleaks/gitleaks/blob/v8.30.1/config/gitleaks.toml): five rules depend on filenames, and global/per-rule path allowlists exist. Neutral object names avoid historical path exclusions for the content pass but do not exercise filename predicates. Keep separate evidence for these rules and preserve all mappings. No content-regex, entropy or acceptance threshold changes are proposed.
9. [Git mktree](https://git-scm.com/docs/git-mktree) and [commit-tree](https://git-scm.com/docs/git-commit-tree): construct an isolated root tree/commit with exact existing object IDs. A private temporary repository can borrow read-only objects; no product branch or reference is rewritten, and no credential-bearing file needs to be checked out.
10. Local signed `S11/history-paths-1/{scope.json,inventory.json.gz}` and independent inventory check: 3,946 frozen commits, 136,617 mappings and 91,187 unique blobs. Raw JSON and HTML account for 3.349 GB and 4.056 GB before content classification. Gzip, PNG metadata, SVG and filename supplements have separate, bounded coverage.

Prespecified study: compare unchanged pinned Gitleaks stdin with isolated synthetic root-commit scanning using identical public invalid marker fixtures and a deterministic real-object sample. Measure elapsed time, exact payload bytes and metadata-only findings. Exercise a recognized application header, a multiline marker larger than a stdin fragment, EOF without newline, CRLF, UTF-8, and filename-sensitive YAML. Root patches must reconstruct every exact source byte with the same EOF and line numbering. Preserve every failed study. The study does not replace the original scanner, claim all-history completion, decode embedded/base64/archives, scan submodules, or cover commits after the frozen inventory. A full scan requires checkpointing, explicit exclusions, a verified path supplement and independent mapping review after this comparison.

Measured study 1: all nine root-commit fixture checks passed. Stdin missed the application-header marker, the large multiline marker and the filename-only YAML case; the first two demonstrate content loss, while the last demonstrates absent filename context. Public markers contain deliberately invalid text, not generated key material. EOF, CRLF, UTF-8 and ignore-inline-suppression checks passed. All synthetic root patches reconstructed the original bytes, line counts and EOF.

For 50 deterministic real objects totaling 19,075,387 B, stdin took 9.421394 s; root construction plus byte audit took 0.282989 s and root scanning took 68.033821 s. Both methods returned the same one metadata finding. Independent review binds every sample through its immutable commit:path and verifies the finding as the explicit local unit-test signing constant in the exact historical `supabase/tests/src/malformed.test.ts` blob, used by its signing helper and expected-HMAC assertion. No value is recorded. Original result remains unresolved in the raw report; the separate review records its classification. No full-history claim follows from this sample.

Decision: the root-commit route is a useful correctness baseline but is about 7.2 times slower than stdin on this sample. Do not start an unvalidated stdin replacement or infer whole-corpus runtime from one sample. Next compare a direct call to the same pinned detector on complete original fragments, retaining its default rules and explicit filename aliases. This can bypass the File source's MIME/framing behavior and Git's patch processing while preserving detection semantics. [Gitleaks v8.30.1 Detector API](https://pkg.go.dev/github.com/zricethezav/gitleaks/v8@v8.30.1/detect#Detector.Detect) and the pinned `detect.go` are the additional primary sources; [its go.mod](https://github.com/gitleaks/gitleaks/blob/v8.30.1/go.mod) specifies Go 1.24.11 or newer. The prespecified comparison required a workspace-local toolchain; the completed build and results follow below.

`history-text-object-study-review-1.json` verifies hashes, source mappings, reductions, the exact test finding and regression comparison; it does not independently replay the discarded synthetic patches or rerun the detector. `history-text-study-regression-1` retains seven identical ART failures and 2,690 web passes; server/rules/typecheck/three-fixture probe/build exit zero. The original text scanner remains active, unmodified and incomplete; global repository/parity gates remain open.

Direct-detector study 1: pinned Gitleaks 8.30.1 with its byte-identical 222-rule embedded config matches all nine root fixtures and all 50 exact historical sample objects. The direct detector took 68.225671585 s (68.259648 s wall), versus 68.033821 s for the verified root scan and 9.421394 s for incomplete stdin. No speed improvement was observed. Four invalid/truncated frames fail closed without raw output; independent review replays those rejects. Go 1.27.4 is workspace-local, downloaded from [official Go distributions](https://go.dev/dl/?mode=json); its archive checksum and compiler bytes are verified. The module graph has 202 records, no replacements, 62 linked dependencies; module verification, binary build metadata, pinned API source and config equality pass. No global toolchain or installed product code changed.

Decision: use the direct route for explicit framing, cancellable owned subprocesses and per-object accounting, not for a speed claim. A supplementary frozen-inventory scan is active and the original scanner remains untouched. Every eligible UTF-8/no-NUL object is scanned once under a neutral text alias, plus all 51 historical YAML contexts; other four filename predicates have no frozen matches. Default content allowlists remain. Binary, NUL, encoded, archive, submodule and later-reference coverage remains open. The neutral staged supplement also scans go.mod/go.sum, which default filename exclusions otherwise skip.

Findings remain unresolved; no classification follows merely from a path. The frozen prefix has no YAML scan yet; the separate mutable scan continues.
