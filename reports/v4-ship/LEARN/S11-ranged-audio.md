Additional primary references read for the codec work:
10. [FFmpeg MP3 muxer](https://ffmpeg.org/ffmpeg-formats.html#mp3): the default Xing/LAME information frame carries duration and encoder delay. Disabling metadata can change decoder behavior; it cannot be assumed to remove signal padding.
11. [FFmpeg MP3 decoder source](https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/mp3dec.c): parses LAME/Lavc delay and padding, accounting for decoder skip; also recognizes iTunes gapless metadata. This motivates a controlled metadata test, not a claim that WebKit uses this implementation.
12. [WebKit Cocoa audio reader](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/platform/audio/cocoa/AudioFileReaderCocoa.mm): platform decoding is a separate implementation from Chromium. Test actual decoded samples rather than infer parity from file support.
13. [LAME command options](https://github.com/lameproject/lame/blob/master/doc/html/detailed.html): accepts float WAV and can write its own LAME tag. Compare a native LAME encode and an iTunes gapless comment with the original; preserve rejected alternatives. No new recording, normalization or generated sound.
14. [Web Audio decodeAudioData](https://www.w3.org/TR/webaudio/#dom-baseaudiocontext-decodeaudiodata): output is resampled to the context sample rate. A48kHz result alone is insufficient for a runtime offset rule on44.1kHz devices.
