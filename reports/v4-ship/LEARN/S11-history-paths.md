# S11 historical filename coverage

Read 16 November 2026 UTC before implementation. The existing textual scanner and its frozen scope stay unchanged. Audio endurance keeps its installed runtime and capture harness unchanged.

1. [NIST SP 800-218 SSDF, PS.3.1](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-218.pdf), formal publication: preserve release files together with integrity and provenance information. Bind scope, source rules, scripts and results by immutable hashes.
2. [Git rev-list](https://git-scm.com/docs/git-rev-list#Documentation/git-rev-list.txt---object-names): object names are hints; a shared object receives only one displayed name. This cannot enumerate every filename at which identical bytes existed.
3. [Git log](https://git-scm.com/docs/git-log): full history follows every parent; root and separate merge comparisons expose historical introductions. Freeze reference tips before walking and retain root changes, removals and renames as additions/deletions.
4. [Git diff-tree raw format](https://git-scm.com/docs/git-diff-tree#_raw_output_format): raw records include modes, object IDs, status and paths; NUL delimiters preserve unusual filename bytes. Disable rename heuristics and retain distinct path/blob pairs.
5. [Git cat-file](https://git-scm.com/docs/git-cat-file): exact commit:path references independently resolve object identity, type and size. Use NUL batch inputs/outputs and inspect link blobs without following links.
6. [Gitleaks documentation](https://github.com/gitleaks/gitleaks): path expressions may be standalone or combined with content expressions. Directory scanning supplies filename context; stdin does not. Use the installed default detector without disabled rules, blanket finding exceptions or size skips.
7. [Gitleaks 8.30.1 default source](https://github.com/gitleaks/gitleaks/blob/v8.30.1/config/gitleaks.toml): five rules have filename predicates, covering PHP, Terraform/HCL, YAML, NuGet config and PKCS12 suffixes. Pin the source blob and enumerate these predicates; unchanged default global exclusions must be disclosed, not silently treated as inspected content.
8. [GitHub secret scanning](https://docs.github.com/en/code-security/concepts/secret-security/secret-scanning): historical branches are part of the exposure surface. Later references and arbitrary binary/encoded contents remain separate from this bounded supplement.

Own measured comparison, `S11/history-path-method-comparison-1.json`: identical 62-byte harmless fixture text was scanned at `.txt`, `.p12` and `.PFX` names. Six default-detector invocations took 0.020883–0.023346 s each. Stdin produced zero findings; directory mode produced two filename-only PKCS12 findings. This demonstrates a filename coverage gap, not an actual leaked credential or a complete-history result.

Selected method: inventory every unique reachable path/blob pair using raw root/per-parent changes, independently verify commit:path mappings, then scan all pairs whose original filenames match any installed path predicate. Store only immutable identity, hashes, counts and redacted location metadata. Never execute historical files or follow historical symlinks. Preserve every finding for contextual review. Other content detectors, default path exclusions, nested archive names, encoded data, unreferenced objects and later references remain open.

Independent controlled-history comparison passed: six commits containing a root, divergent branches, a two-parent merge, rename, deletion, newline filename, symlink and Gitlink. Raw changes and the union of every tree both found seven path/object pairs in 0.024795 s and 0.058028 s respectively. Object-name hints represented only two of six blob paths. The test read link bytes without following them and executed no historical files; `S11/history-path-inventory-check-1.json` binds both scripts.

Completed frozen superproject scope: 3,946 commits, 136,617 unique path/object pairs and 91,187 unique blobs. An independent binary-tree traversal verified all 136,617 pairs across 33,428 tree objects (55,681,033 bytes) in 3.441 s. All 51 matching versions completed default-detector invocations; 19 original pnpm-lock.yaml versions were excluded by the default path filter. Those exact 19 payloads were additionally scanned under payload.yaml, retaining the same positive YAML rule predicate with all default rules enabled: zero findings. The remaining 32 original-name scans also have zero findings. This does not clear unreferenced objects, submodule contents, binary/encoded content, nested archive filenames, the unfinished textual scanner or later references.

Initial inventory failed on two Gitlink responses labelled submodule rather than ordinary object metadata; a diagnostic first assumed missing objects and failed its assertion. Both observations and the exact original scripts are preserved in history-paths-1/attempt-1.json and its hashed compressed harness archive. The corrected implementation verifies immutable ls-tree mode/object entries without following submodules. Expanded controlled-history check2 passes eight pairs, including an unavailable external Gitlink; the independent final review also verifies both original and corrected harness bindings.

Full history-path-regression-1 completed: server/rules/typecheck/three-fixture probe/build exit0; web 2,690 passed and the identical seven ART failures. Comparison1 binds the exact failing test identities. G-REG and official class parity remain false.
