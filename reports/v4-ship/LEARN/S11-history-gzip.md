# S11 historical gzip coverage

Read 16 November 2026 UTC before building the content scanner. The frozen textual Git scanner remains active and unchanged. This item extends its explicitly excluded gzip surface.

1. [RFC 1952, formal GZIP format](https://www.rfc-editor.org/rfc/rfc1952): gzip wraps compressed members with integrity information, including CRC32 and uncompressed size. Detector checks on compressed bytes do not establish checks on the original text.
2. [Python gzip documentation](https://docs.python.org/3/library/gzip.html): `decompress` supports concatenated gzip members. Consume complete members; corruption must remain a failed/incomplete check.
3. [Gitleaks documentation](https://github.com/gitleaks/gitleaks): archive traversal defaults to zero; stdin accepts a content stream. Preserve the installed default detectors, redaction and unlimited target size. This supplement checks expanded content through stdin, so it must not claim path-sensitive or arbitrary embedded-archive coverage.
4. [Git log documentation](https://git-scm.com/docs/git-log): full-history walks all parents; root and per-parent merge changes expose introductions on branches. Capture ref tips and keep the case-insensitive gzip path scope explicit.
5. [Git cat-file documentation](https://git-scm.com/docs/git-cat-file): exact object IDs supply immutable blob bytes; batch checks independently resolve each captured commit/path to its expected object type and size.
6. [GitHub secret scanning](https://docs.github.com/en/code-security/concepts/secret-security/secret-scanning): historical versions on all branches remain an exposure surface. A clean current tree is insufficient evidence for those versions.

Inventory: `S11/history-gzip-1/scope.json` captures 7,103 gzip changes, 15 deletions and 1,332 unique blobs totaling 7,218,889,535 compressed bytes. The independent commit/path checks match all 1,332 object IDs and sizes. Only hashes, locations and measurements are persisted; compressed Git objects remain in Git.

Own experiment before implementation: wrap four exact historical blobs with previously reviewed non-secret detector matches in gzip, in memory. Compare raw gzip bytes, expanded gzip bytes and the original text using the same installed default detector. Raw gzip yields 0 findings; both expanded and original text yield 4, with identical rule/line locations in all four samples. This is a coverage demonstration, not a clean-history result or a speed benchmark. See `S11/history-gzip-comparison-1.json`.

Use a frozen, resumable per-blob scanner. Verify the Git object identity, compressed and expanded hashes, and gzip integrity; retain only redacted finding metadata. Process smaller blobs first for durable progress, without skipping large ones. Exact expanded-byte hashes may reuse an earlier identical stdin result, since the detector input and configuration are identical; record that dependency explicitly. Errors and interruptions leave the blob incomplete. Raw data and detector output stay in process memory.

Do not label the full history clean. The original textual scan, contextual triage, later refs, path-sensitive detector behavior and other binary/archive formats remain separate. No ART file, deployed service, rule, image or browser interaction is changed.
