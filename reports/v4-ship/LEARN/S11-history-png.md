# S11 historical PNG text metadata

Read 16 November 2026 UTC before implementation. Inspect immutable Git bytes without rendering images, decoding pixels, editing ART files, generating artwork, or following metadata links. Do not expose metadata values or generator inputs in reports.

1. [W3C PNG Third Edition](https://www.w3.org/TR/png-3/#11textinfo), formal Recommendation: text is carried by tEXt, zTXt and iTXt. The latter two can require zlib expansion; iTXt uses UTF-8 while tEXt/zTXt use Latin-1. Chunk framing and CRC validation are distinct from decoding pixels.
2. [RFC 1950](https://www.rfc-editor.org/rfc/rfc1950), formal format specification: zlib contains checksummed compressed bytes. Data after the stream are separate; reject silent trailing or incomplete compressed input.
3. [Python 3.12 zlib](https://docs.python.org/3.12/library/zlib.html): bounded decompression exposes eof, unconsumed_tail and unused_data. A resource ceiling must produce an explicit incomplete result, never a successful scan with discarded text.
4. [Python struct](https://docs.python.org/3/library/struct.html): explicit big-endian integer formats avoid native alignment and byte-order assumptions. Check every chunk boundary before slicing.
5. [Git cat-file](https://git-scm.com/docs/git-cat-file): persistent batch mode yields exact object type, byte count and content in requested order. Verify framing, the Git blob ID and SHA-256; do not follow submodules or symlinks.
6. [Gitleaks 8.30.1 commands](https://raw.githubusercontent.com/gitleaks/gitleaks/v8.30.1/README.md): stdin receives decoded text without filename filters. Preserve default rules and full redaction; no new baseline or detector exclusion.
7. [Pinned default detector configuration](https://raw.githubusercontent.com/gitleaks/gitleaks/v8.30.1/config/gitleaks.toml): PNG filenames are globally skipped. The five positive path rules do not target PNG paths; explicit text extraction is supplemental content coverage.
8. Local independently reviewed frozen inventory: 3,946 commits, 64,003 PNG path/blob pairs, 27,892 unique blobs, 12,985,353,108 bytes. Later references require a separate inventory.

Measured comparison before implementation: 128 evenly spaced OIDs selected from the sorted frozen PNG set, 57,889,363 bytes. Separate cat-file processes took 1.352948 s; a persistent batch took 0.166347 s. Both independently verified every Git ID and returned identical SHA-256 hashes. Select persistent batch; this is a throughput observation, not secret-scan acceptance. See `S11/history-png-method-comparison-1.json`.

Prespecified scope: verify chunk framing/CRC and extract all three standard text chunk types, including keywords and international language/translated-keyword fields. Deduplicate identical extracted text by SHA-256 while retaining complete object/chunk mappings. Keep malformed framing, invalid encoding, unexpected compression, trailing bytes and resource-limit cases explicitly unresolved. Scan only in memory and persist hashes, sizes, detector names and locations. EXIF, ICC profiles, unknown chunks, compressed pixel data, steganography, encoded subcontent, archives, submodules and later refs remain outside this supplement; no complete binary/history gate claim follows.

There were 27,466 tEXt chunks and no zTXt/iTXt chunks; 3,107 unique decoded inputs (82,017 bytes) yielded zero findings. Six non-PNG signatures remain explicitly unscanned.
