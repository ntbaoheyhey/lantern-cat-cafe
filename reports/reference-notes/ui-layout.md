# Information layout observations

Evidence: archived page text and accessibility snapshots for grades,
stats, pets, gear details, skills, and the rune planner; the earlier
overview and coverage proposals. Public HTML for the landing page and
the corresponding system pages was checked on 2026-11-02.
No screenshots, stylesheet files, image assets, or site code were used.

## Navigation and discovery

The captured navigation groups related subjects, then offers search and
links into individual records. Pages separate a short explanation from a
larger catalogue or tool. Cross-links connect an object to its acquisition
source, a stat to its explanation, and an upgrade to its prerequisites.
This reduces the need to remember which subsystem owns a question.

Browse controls operate on independent axes: equipment position,
eligibility, quality, and level. A selected record exposes its detailed
numbers without making those details part of every catalogue entry.
Comparison is an explicit step; the grade page can compare selected ranks.

## Details and uncertainty

An item detail groups identity and eligibility before stat lines, then
conversion value and acquisition routes. Stacking behavior belongs beside
the affected stat. A source qualification or uncertain cap belongs beside
the numeric claim, rather than only in a distant methodology page.

Probability views should expose the eligible pool, denominator, precision,
and conditions. Container acquisition, container contents, and session
history answer different questions. A visual streak counter alone should
not imply a promise about the next result.

Companion entries pair progress with benefit; account trees pair
prerequisites and marginal cost with accumulated effect. Hypothetical plans
must stay visibly distinct from owned progress. The captured planner
provides navigation aids and a purchase trace for a large dependency graph.

## Transferable hierarchy, not a screen specification

For our own interface, the useful reading order is: current state,
next actionable choice, expected effect or cost, then supporting detail.
Show our actual rules and available features in that hierarchy.
Research-only mechanics should not appear as working product controls.

This review concerns information relationships and reading order.
Static HTML and archived accessibility text cannot establish responsive
breakpoints, pixel spacing, keyboard behavior, contrast, or animation
quality. No visual fidelity or accessibility test of the live site is
claimed, and no source page layout is proposed for reproduction.
