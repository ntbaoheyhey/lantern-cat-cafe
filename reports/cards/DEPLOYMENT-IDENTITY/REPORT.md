# Public deployment artifact identity — living draft

Current baseline: the public site's entry manifest and all 31 emitted non-HTML files match byte-for-byte a clean production v2 build of main `1fb25edf4c54ada0d161e3c1dd16a4c4550aafba`. Evidence: `main-complete-baseline/result.json`. GitHub independently reports successful Vercel statuses for that SHA in `main-status.json`. This establishes current artifact equivalence; Vercel's private commit metadata was not observed. The deployment dashboard requires login in the available browser, and no authentication or environment change was attempted.

The earlier 17-bundle comparison is preserved in `main-baseline/`; the complete comparison additionally includes public images, favicon and Relic resources. Each directory retains its exact helper as run. Configuration is observed from the public entry scripts in memory and is never recorded. Source checkout HEAD and tracked build inputs are checked before and after the build. Every resource must return 200 with the same SHA-256, and the HTML entry manifest must remain unchanged across the collection. No request ID, local HEAD alone, stale cached asset URL or HTML declaration is treated as a deployed SHA.

Controls: five Node test cases reject missing/changed entry points, changed bytes, HTTP errors, empty evidence and a deployment changing during collection. An additional real negative control uses the exact BASE0 candidate's existing G5 build: its entry manifest differs from current live and returns `ENTRY_MISMATCH` (`candidate-negative-control.json`). The unmerged candidate is therefore not mislabeled live.

After a permitted merge, first complete the prescribed clean-main checks. Then obtain successful Vercel status for the exact merged SHA and run the helper from that clean checkout with a fresh evidence directory. Require `ARTIFACT_MATCH` and the phased live judge path. Record these as content verification and status evidence. If different commits emit identical files, this method cannot distinguish which commit Vercel internally recorded; retain that limit and seek provider metadata if that exact distinction is required. It never authorizes skipping a red or pending deployment, modifying live configuration, or claiming unseen metadata.

Invocation: `node reports/cards/DEPLOYMENT-IDENTITY/artifact-identity.mjs ABSOLUTE_CLEAN_CHECKOUT EXACT_40_CHARACTER_SHA ABSOLUTE_NEW_EVIDENCE_DIRECTORY 1` for the currently observed live v2 mode. Preserve the existing live mode; mode `0` supports classic. The helper never changes hosting settings. Logs are local, and only hashes, public resource paths and booleans enter the report.

No merge or postmerge verification has happened. This card provides a tested read-only method for that later gate.
